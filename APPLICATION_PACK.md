# Application Pack

This repository contains multiple resume layers because one resume should not try to carry the entire portfolio into every application.

## Default Resume Selection

Use **RESUME_ATS_ONE_PAGE.md** for most applications where an ATS or recruiter will scan quickly.

Use **RESUME_AUTOMATION_SOFTWARE.md** when the role is strongly software/automation focused and allows a longer technical resume.

Use **RESUME_TECHNICAL_IMPLEMENTATION.md** for implementation, technical operations, application support, technical project coordination, and customer-facing technical roles.

Use **CAPABILITY_MATRIX.md**, **CASE_STUDIES.md**, **PROJECT_RESUME.md**, and **PROJECT_INDEX.md** as the evidence layer when tailoring the application or preparing for interviews.

## Tailoring Gate

Before submitting an application:

1. Copy the job description into a scratch document.
2. Identify the 8-15 repeated or high-value technical terms.
3. Compare them with `ATS_KEYWORD_MAP.md` and `CAPABILITY_MATRIX.md`.
4. Add only terms supported by real project evidence.
5. Move the 2-4 most relevant projects higher in the resume.
6. Match the headline to the actual role title where truthful.
7. Remove project details that do not help that specific application.
8. Keep the resume simple: one column, standard headings, no graphics, no skill-rating bars, no dense tables.
9. Export to PDF only after verifying the text remains selectable and copyable.
10. Keep the GitHub profile URL visible so deeper evidence is one click away.

## Evidence Rule

Never add a keyword simply because the employer listed it.

Use this classification:

- **STRONG:** repeated operational or project evidence; safe to feature prominently.
- **IMPLEMENTED:** real project evidence; safe to list, but do not imply years of production employment.
- **EXPERIMENTAL / RESEARCH:** mention only when useful and label appropriately.
- **UNKNOWN / INVENTORY ONLY:** do not put on the resume until verified.

## Application Positioning

The short resume should communicate four things quickly:

1. Victor writes and operates real software systems, primarily in Python and automation.
2. He can work across application code, APIs, testing, Git/GitHub, Linux, deployment, and troubleshooting.
3. His project work demonstrates multi-agent/AI automation, internal tooling, reliability, backend services, and technical operations.
4. His current armed-security role is not hidden; it is positioned as current professional experience while the software portfolio provides the technical evidence.

## Interview Proof Order

When asked for examples, prioritize:

1. Dream.OS — architecture, task/message lifecycle, guarded execution, verification.
2. AgentTools — reusable multi-agent coordination/tooling.
3. ProjectScanner — evidence-first repository intelligence.
4. Dream.OS Swarm Brain — FastAPI/SQLite service and operational state.
5. Website deployment system — CI/CD, SFTP, HTTPS verification, troubleshooting.
6. Message-bus runtime recovery — debugging, source archaeology, regression tests.

Then choose a domain project based on the employer:

- education → HomeSchool Mastery
- networking/security → Network Scanner
- trading/fintech → TradingRobotPlug
- media/computer vision → MeTuber
- game development → Digital Dreamscape
- AI knowledge/memory → DreamVault / Thea / FocusForge

## Compensation Target

Primary search lane: roles that materially improve on current compensation and provide direct technical career capital. The working search target is roughly **$50,000-$70,000+ annual compensation**, adjusted for role quality, benefits, remote/hybrid fit, and software-development trajectory.
