## Reliability / Engineering Operating Model

- Make the smallest safe change that can close the immediate problem.
- Verify the real runtime/product path instead of trusting a scratch harness alone.
- Separate canonical source, generated output, salvage, historical evidence and runtime state.
- Preserve useful work before deletion or consolidation.
- Prefer machine-readable JSON/YAML plus human-readable closeouts/reports.
- Use targeted regression tests and negative controls for important enforcement behavior.
- Treat environment, billing, networking and dependency failures separately from product defects.
- Leave a readable handoff: target, action, verification, result and next state.
